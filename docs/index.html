Netlink

Neuereatec multi-connection downloader for Windows

Netlink downloads different parts of the same file through each internet connection you select, then assembles them on disk. It combines connections for its own downloads and requires no VPN or virtual network adapter.

Download for Windows (v1.0.0)

How Netlink works

Beginner

  1. Netlink downloads different parts of the same file through each internet connection you select, then puts the parts back together on your disk.
  2. You don’t need a VPN or any virtual network adapter.
  3. Netlink doesn’t create a bonded or virtual IP. Each connection keeps its own public IP, and the parts are put back together by software on your computer.
  4. A public speed test can’t show the combined speed. A speed test uses a single connection, so it rides whichever one connection your computer sends it over (one link), not all of them.
  5. The real measure is a multi-part download: for example, a large file finishing faster than any single connection could deliver it. Netlink shows the speed of each connection and the total.
  6. Honest caveat: you can’t predict the exact speed gain beforehand. It depends on your connections, the download server (whether it lets files be downloaded in parts, and how many parts at once it allows), and how well the parts can be downloaded side by side.

Advanced

  1. Netlink splits one file into byte ranges and fetches them with HTTP Range requests (RFC 9110 §14), spread across the internet connections you select.
  2. Each TCP connection is pinned to one interface: on Linux with SO_BINDTODEVICE, on Windows and macOS by binding the socket’s source address (Node’s localAddress). The OS’s interface selection then sends it out that connection, so it uses that connection’s own public IP. No VPN, TUN device or virtual adapter is involved.
  3. No bonded IP or virtual IP is created. Parts are fetched in parallel from a shared queue and written at their own offsets into one staging file (positional writes), which is renamed to the final file when complete. All reassembly is done in software on that machine.
  4. A public speed test is one TCP flow (or a few on one route), so it rides one connection, not all of them. A test server receiving Netlink’s parallel requests would instead see distinct source IPs, one per connection.
  5. The real measure is multi-part download throughput: a large file finishing faster than any single connection could deliver it. Netlink shows per-connection and total speed.
  6. The gain can’t be predicted exactly. It depends on per-link capacity, whether the server supports range requests and its per-client connection limits, latency, and disk speed.
  • Each connection you select must be its own internet connection (e.g. two different ISPs, or Wi-Fi plus a phone hotspot).
  • It only speeds up downloads done inside the Netlink app, not your browser or other programs.

OpenWrt (preview)

Preview, not yet tested on real hardware. Router testing is the next step.

Netlink for OpenWrt runs the same downloader on the router itself. It downloads different parts of the same file through each WAN connection, then assembles them on the router's disk. Any device on your LAN can use it from a web page on the router. No firmware rebuild, VPN, tunnel or bonded IP is needed: each connection keeps its own public IP. It is one small program (no Node needed), with a procd service and a UCI config.

Find your router's architecture with grep ARCH /etc/openwrt_release, then download its package:

  • mipsel_24kc (MT7621 / MT76x8): .ipk · .tar.gz
  • mips_24kc (ath79): .ipk · .tar.gz
  • arm_cortex-a7_neon-vfpv4 (ipq40xx): .ipk · .tar.gz
  • arm_cortex-a9 (mvebu): .ipk · .tar.gz
  • aarch64_cortex-a53 (filogic, Raspberry Pi): .ipk · .tar.gz
  • aarch64_generic (rockchip, others): .ipk · .tar.gz
  • x86_64 (PC / VM): .ipk · .tar.gz

OpenWrt 24.10 and older (opkg): copy the .ipk to /tmp on the router, then run opkg install /tmp/netlink_0.1.0-1_<arch>.ipk.
OpenWrt 25.12 and newer (apk), or any release: copy the .tar.gz to /tmp, then run tar -xzf /tmp/netlink-openwrt_0.1.0_<arch>.tar.gz -C / && /etc/init.d/netlink enable.

Setup: set each WAN connection's device in /etc/config/netlink (one config wan section per connection: wan1, wan2, …). ifstatus wan | grep l3_device shows a connection's device. Then run /etc/init.d/netlink restart and open http://<router>:8099 from a LAN device. Paste a link, choose the connections, and save the finished file to your device.

  • Each connection must be its own WAN interface on the router, with its own route. They must not be bonded or merged into one interface beforehand.
  • It only speeds up downloads made through Netlink's router page, not normal browsing, streaming or speed tests.
  • The download server must support range requests (most mirrors and CDNs do). Otherwise it uses one connection.
  • Downloads go to RAM (/tmp) by default. Use USB storage for large files. Keep port 8099 on the LAN.

Full instructions are in the OpenWrt README. Checksums are in SHA256SUMS.

Installing

The installer is not code-signed, so Windows SmartScreen may show “Windows protected your PC”. Click More info → Run anyway.
